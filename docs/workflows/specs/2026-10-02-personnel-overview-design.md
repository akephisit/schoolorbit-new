# ภาพรวมงานบุคคลและข้อมูลบุคลากรมาตรฐาน

วันที่: 2026-10-02 · สาขา: `feat/personnel-overview` · ฐาน: `3ed513ea`

## เป้าหมายที่ตกลงในบทสนทนา

เพิ่มหน้าภาพรวมให้ผู้ดูแลงานบุคคลเห็นจำนวนบุคลากร แยกตามกลุ่มสาระ ตำแหน่งงาน วิทยฐานะ และวุฒิการศึกษาสูงสุด พร้อมเปิดดูรายชื่อจากกราฟได้ ข้อมูลที่ใช้จัดกลุ่มต้องมีค่ามาตรฐาน เพื่อไม่ให้การสะกดต่างกันทำให้การกรองและการนับผิดพลาด

คำว่า “ตำแหน่งงาน” หมายถึงตำแหน่งของบุคลากร เช่น ครู ครูผู้ช่วย และครูอัตราจ้าง ส่วนวิทยฐานะเป็นอีกช่องหนึ่ง บทบาทสิทธิ์ในระบบและหน้าที่ในหน่วยงานยังเป็นข้อมูลคนละประเภท กลุ่มสาระต้องอ่านจากสังกัดเดิมในระบบ ไม่เพิ่มช่องให้กรอกสังกัดซ้ำในข้อมูลบุคลากร

ขอบเขตนี้รวมฐานข้อมูล API แบบฟอร์มเพิ่ม/แก้ไข หน้ารายละเอียด รายชื่อ ตัวกรอง Dashboard และการดูแลรายการอ้างอิง ใช้ขั้นตอนพัฒนางานเชิงโครงสร้าง โดยเอกสารนี้เป็นแบบสำหรับตรวจ ก่อนจัดทำแผนลงมือทำและเปลี่ยนโค้ดจริง

## แนวทางที่เลือก

ใช้รหัสมาตรฐานสำหรับวิทยฐานะและระดับวุฒิ และใช้รายการกลางของแต่ละโรงเรียนสำหรับตำแหน่งงาน สาขาวิชา และสถาบันการศึกษา รายการกลางมี ID ถาวร เลือกค้นหาได้ และผู้มีสิทธิ์แก้ไขบุคลากรดูแลรายการได้

การใช้รายการตายตัวทั้งหมดจะเพิ่มตำแหน่งหรือสาขาวิชาของโรงเรียนได้ยาก ส่วนการให้ทุกช่องเป็นข้อความจะยังเกิดปัญหาการสะกดและการจัดกลุ่ม แนวทางผสมนี้รองรับทั้งข้อมูลที่มีชุดค่าชัดเจนและข้อมูลที่โรงเรียนต้องเพิ่มเอง

## ข้อมูลและเจ้าของ

| ข้อมูล             | วิธีกรอกและจัดเก็บ                           | เมื่อยังไม่มีข้อมูล                     |
| ------------------ | -------------------------------------------- | --------------------------------------- |
| ตำแหน่งงาน         | เลือกรายการกลาง เก็บ `job_position_id`       | `null` = ยังไม่ระบุ                     |
| วิทยฐานะ           | เลือกรหัสมาตรฐาน `academic_rank`             | `null` = ยังไม่ระบุ แยกจากไม่มีวิทยฐานะ |
| วุฒิการศึกษาสูงสุด | เลือกรหัสมาตรฐานใน `education_level`         | `null` = ยังไม่ระบุ                     |
| สาขาวิชา           | ค้นหาและเลือกรายการกลาง เก็บ `major_id`      | `null` = ยังไม่ระบุ                     |
| สถาบันการศึกษา     | ค้นหาและเลือกรายการกลาง เก็บ `university_id` | `null` = ยังไม่ระบุ                     |
| กลุ่มสาระ          | อ่านสมาชิกหน่วยงานที่เชื่อมกับกลุ่มสาระ      | หมวด “ยังไม่มีสังกัดกลุ่มสาระ”          |

ข้อมูล HR อยู่ใน `staff_info` ตามเจ้าของเดิม ข้อมูลชนิดการจ้าง (`employment_type`) ซึ่งมีอยู่แล้วในฐานข้อมูล ใบอนุญาตประกอบวิชาชีพ metadata และความสัมพันธ์อื่นต้องรักษาไว้ ไม่สร้างชนิดการจ้างซ้ำและไม่แปลงจากตำแหน่งงานโดยคาดเดา

วิทยฐานะใช้รหัส `none` (ไม่มีวิทยฐานะ), `not_applicable` (ไม่ใช้กับตำแหน่งนี้), `proficient` (ชำนาญการ), `senior_proficient` (ชำนาญการพิเศษ), `expert` (เชี่ยวชาญ) และ `senior_expert` (เชี่ยวชาญพิเศษ) ผู้ดูแลเป็นผู้ระบุข้อมูล ไม่อนุมานจากบทบาท ตำแหน่ง หรือสังกัด และไม่เพิ่มกฎตัดสินคุณสมบัติทางกฎหมายในงานนี้

ระดับวุฒิใช้รหัส `primary`, `lower_secondary`, `upper_secondary`, `vocational_certificate`, `higher_vocational`, `diploma`, `bachelor`, `master`, `doctorate` และ `other` แสดงชื่อไทยตามลำดับ ประถมศึกษา มัธยมศึกษาตอนต้น มัธยมศึกษาตอนปลาย ปวช. ปวส. อนุปริญญา ปริญญาตรี ปริญญาโท ปริญญาเอก และอื่น ๆ ช่องนี้เก็บวุฒิสูงสุดหนึ่งค่า ไม่สร้างประวัติการศึกษาหลายรายการในงานนี้

รายการตำแหน่งเริ่มต้นประกอบด้วย ครู ครูผู้ช่วย ครูอัตราจ้าง พนักงานราชการ (ครู) ผู้อำนวยการสถานศึกษา รองผู้อำนวยการสถานศึกษา และเจ้าหน้าที่สนับสนุน โรงเรียนเพิ่มตำแหน่งเฉพาะของตนได้ สาขาวิชาและสถาบันเริ่มจากค่าที่มีอยู่จริง ไม่ใส่รายการตัวอย่างลงข้อมูลจริง

### รายการอ้างอิง

เพิ่มตาราง `staff_reference_items` ในฐานข้อมูลของแต่ละโรงเรียน มี UUID, ชนิด (`job_position`, `major`, `university`), รหัสคงที่, ชื่อ, ชื่อที่ normalize สำหรับตรวจซ้ำ, สถานะใช้งาน, ลำดับ และเวลาแก้ไข ใช้ unique constraint ของชนิดกับรหัส และชนิดกับชื่อที่ normalize

การ normalize ใช้การตัดช่องว่างหัวท้าย รวมช่องว่างซ้ำ และเปรียบเทียบอักษรภาษาอังกฤษโดยไม่แยกตัวพิมพ์ ไม่รวมชื่อย่อกับชื่อเต็ม และไม่เดาว่าสถาบันหรือสาขาสองชื่อเป็นรายการเดียวกัน

เพิ่ม `/staff/manage/reference-data` เป็นหน้าลูก มีรายการแบบแบ่งหน้า ค้นหา เพิ่ม เปลี่ยนชื่อ และเปิด/ปิดใช้งานตามชนิด ไม่ลบรายการจริง รหัสและ ID เปลี่ยนไม่ได้ การเปลี่ยนชื่อจะแสดงชื่อใหม่ในบุคลากรเดิมที่อ้างอิง ID นั้น การปิดใช้งานหยุดการเลือกใหม่ แต่บุคลากรเดิมยังแสดงรายการนั้นได้พร้อมป้ายสถานะ ผู้แก้ไขสามารถคงรายการเดิมหรือเลือกใหม่ได้

ตัวเลือกค้นหามีขอบเขตสูงสุด 50 รายการต่อคำขอ พร้อมการค้นหาและ pagination การจัดการรายการใช้หน้าแบ่งหน้า ไม่ดึงทั้งตารางให้ browser คัดกรองเอง ค่าที่เลือกไว้ได้รับ ID และชื่อจาก profile จึงแสดงได้แม้ไม่อยู่ในผลค้นหาปัจจุบัน

## หน้าภาพรวม

เพิ่ม `/staff/manage/overview` และลิงก์ “ภาพรวมงานบุคคล” ในส่วนงานบุคคล ใช้ `PageShell` และรูปแบบสี/การ์ดของระบบ รายชื่อและหน้ารายละเอียดมีทางไปภาพรวม ส่วนภาพรวมมีปุ่มไปยังรายชื่อและปุ่มเพิ่มบุคลากรตามสิทธิ์

| พื้นที่    | การนำเสนอ                                            | วิธีอ่าน                                        |
| ---------- | ---------------------------------------------------- | ----------------------------------------------- |
| จำนวนรวม   | การ์ดจำนวนบุคลากรทั้งหมด สถานะใช้งาน และสถานะอื่นรวม | ยอดในขอบเขตที่ผู้ใช้มีสิทธิ์อ่าน                |
| สถานะ      | แผนภูมิวงแหวนพร้อมชื่อ จำนวน และสัดส่วน              | แยกใช้งาน ปิดการใช้งาน ระงับ ลาออก เกษียณ       |
| กลุ่มสาระ  | กราฟแท่งแนวนอน เรียงจำนวนมากไปน้อย                   | รองรับชื่อไทยยาว แสดงจำนวนคนที่แต่ละกลุ่ม       |
| ตำแหน่งงาน | กราฟแท่งแนวนอน                                       | แสดงตำแหน่งจริงและหมวดที่ยังไม่ระบุ             |
| วิทยฐานะ   | กราฟแท่งแนวนอนตามลำดับระดับ                          | แยกไม่ใช้กับตำแหน่ง ไม่มีวิทยฐานะ และยังไม่ระบุ |
| วุฒิสูงสุด | กราฟแท่งแนวนอนตามลำดับระดับวุฒิ                      | มีหมวดที่ยังไม่ระบุ                             |

การ์ดจำนวนและวงแหวนแสดงบุคลากรทุกสถานะในขอบเขตสิทธิ์เสมอ กราฟแจกแจงทั้งสี่มีตัวกรองสถานะร่วมกัน เริ่มที่ “ใช้งาน” และเลือกทุกสถานะหรือแต่ละสถานะได้ มีข้อความบอกขอบเขตและตัวกรองชัดเจน ไม่เรียกสถานะบัญชี `active` ว่าเป็นหลักฐานว่าบุคลากรกำลังปฏิบัติงานจริง

หมวดตำแหน่ง วิทยฐานะ และวุฒินับคนหนึ่งครั้งต่อกราฟ รวมหมวดที่ยังไม่ระบุแล้วต้องเท่ากับจำนวนคนหลังกรองสถานะ กลุ่มสาระอาจรวมมากกว่าจำนวนคนได้เพราะคนหนึ่งมีหลายสังกัด จึงแสดงคำอธิบายไว้ในกราฟกลุ่มสาระและไม่ใช้วงกลมแสดงสัดส่วนกลุ่มสาระ

กราฟทุกอันมีชื่อ จำนวน และรายการข้อความที่เข้าถึงด้วย keyboard/screen reader ได้ ไม่ใช้สีเป็นข้อมูลเพียงอย่างเดียว ค่าเป็นศูนย์ยังอ่านได้และไม่สร้างลิงก์ที่ไม่มีผลลัพธ์ บนมือถือแสดงคอลัมน์เดียว ชื่อไม่ถูกตัดจนแยกหมวดไม่ได้ กราฟใช้ CSS/SVG ใน component ของงานบุคคล ไม่เพิ่ม chart library สำหรับกราฟเรียบง่ายชุดนี้

คลิกหมวดกราฟที่มีข้อมูลเพื่อเปิด `/staff/manage` พร้อมตัวกรองหมวดและสถานะเดียวกับกราฟ วงแหวนส่งสถานะของชิ้นที่คลิก การ์ดจำนวนรวมและสถานะใช้งานมีลิงก์รายชื่อ ส่วนการ์ดรวมสถานะอื่นแสดงจำนวนโดยไม่สร้างค่า filter ที่ขัดกับสถานะ `inactive` ซึ่งมีความหมายเฉพาะอยู่แล้ว

### การนับกลุ่มสาระ

อ่าน `organization_members` ของบุคลากร → `organization_units` ที่ยัง active และ `unit_type = 'subject_group'` → `subject_groups` ที่ active ผ่าน `subject_group_id` ใช้วันปัจจุบันของฐานข้อมูลเดียวกันทั้ง aggregate และตัวกรองรายชื่อ

สมาชิกปัจจุบันต้องเริ่มแล้ว (`started_at <= CURRENT_DATE`) และยังไม่สิ้นสุด (`ended_at IS NULL OR ended_at > CURRENT_DATE`) นับ distinct `(user_id, subject_group_id)` เพื่อไม่ให้นับซ้ำเมื่อหลายหน่วยงานเชื่อมกลุ่มสาระเดียวกัน คนที่ไม่มีความสัมพันธ์ดังกล่าวอยู่ในหมวด “ยังไม่มีสังกัดกลุ่มสาระ” ไม่อนุมานกลุ่มสาระจากวิชาที่สอนหรือชื่อบทบาท

การเปลี่ยนสังกัด การปิดหน่วยงาน หรือการเปลี่ยนข้อมูล HR มีผลในการอ่านครั้งถัดไป หน้าแสดงเวลาอ้างอิงข้อมูลและมีปุ่มรีเฟรช ไม่เก็บ cache บุคลากรระยะยาว และไม่เพิ่มระบบประวัติจำนวนบุคลากรย้อนหลังในงานนี้

## แบบฟอร์มและรายชื่อ

หน้าเพิ่มบุคลากรเพิ่มส่วน “ตำแหน่งและการศึกษา” ในขั้นข้อมูลของ wizard เดิม และแสดงข้อมูลที่เลือกในขั้นตรวจทาน หน้าแก้ไขใช้ส่วนที่ตั้งชื่อชัดเจนพร้อม deep link โดยคงการเตือนข้อมูลที่ยังไม่บันทึก การส่งเฉพาะค่าที่เปลี่ยน และการแยกการจัดการสิทธิ์/สังกัดที่ทำไว้แล้ว

ช่องมาตรฐานเลือกค่าได้ รวมตัวเลือก “ยังไม่ระบุ” เพื่อไม่บังคับเติมข้อมูลที่ยังตรวจไม่ได้ การส่งค่าที่มีรูปแบบผิด รายการต่างชนิด หรือรายการปิดใช้งานที่ไม่ใช่ค่าปัจจุบันถูกปฏิเสธจาก backend สาขาวิชาและสถาบันใช้ตัวเลือกที่ค้นหาได้ ผู้มีสิทธิ์แก้ไขบุคลากรเข้าหน้ารายการกลางจากแบบฟอร์มได้ และรีเฟรชตัวเลือกหลังเพิ่มรายการ

รายละเอียดแสดงตำแหน่งงาน วิทยฐานะ วุฒิ สาขา และสถาบัน พร้อมชื่อมาตรฐาน ถ้าไม่มีข้อมูลแสดง “ยังไม่ระบุ” กลุ่มสาระแสดงจากสังกัดและมีทางไปจัดการสังกัดตามสิทธิ์ หน้ารายชื่อแสดงตำแหน่งและวิทยฐานะอ่านง่าย และเพิ่มตัวกรองตำแหน่ง วิทยฐานะ วุฒิ และกลุ่มสาระ โดยใช้ตัวกรองส่วนเพิ่มเติมที่มีอยู่

เพิ่ม query parameters `job_position_id`, `academic_rank`, `education_level`, `subject_group_id` โดยช่องที่มีหมวดข้อมูลว่างรองรับ token `unspecified` ที่ตรวจชนิดได้ชัดเจน และกลุ่มสาระใช้ token `unassigned` ไม่ใช้ UUID ปลอม รหัสเหล่านี้ใช้เฉพาะการกรอง ไม่เก็บเป็นข้อมูลบุคลากร

ทั้งการนับ total การโหลดหน้า และการคลิกจากกราฟใช้ predicate เดียวกัน รักษา search/status/ตัวกรอง/pagination ใน URL และ allowlist ของ return context เพื่อกลับจากรายละเอียดหรือแก้ไขมายังผลกรองเดิมได้ ไม่เปลี่ยนตัวกรองบทบาทและหน่วยงานเดิมให้หมายถึงตำแหน่งงาน

## API ขอบเขตสิทธิ์ และการโหลด

เพิ่ม typed domain endpoint `GET /api/staff/personnel-overview` สำหรับยอดและกราฟของข้อมูล HR ชุดเดียว และ `GET/POST /api/staff/reference-items` กับ `PATCH /api/staff/reference-items/{id}` สำหรับรายการอ้างอิง ใช้ envelope ของระบบและลงทะเบียน DTO/path ใน OpenAPI ก่อนสร้าง TypeScript contracts

aggregate ใช้ชุดบุคลากรที่ผ่าน authorization ก่อน แล้วจึงจัดกลุ่มด้วย set-based SQL ไม่โหลด profile ทุกคน ไม่ส่งชื่อหรือข้อมูลส่วนบุคคลมาเพื่อให้ frontend นับเอง และไม่เรียก API home dashboard เดิมซึ่งมีขอบเขตและ academic context ต่างกัน

Dashboard และ directory ต้องใช้ resource policy ของ `staff_profile.read.own`, `.organization_unit`, `.organization_tree`, `.school` ตรงกัน คนที่อ่านได้เฉพาะตนเองต้องไม่เห็นยอดทั้งโรงเรียน สิทธิ์สร้างผลงานไม่ทำให้ได้อ่านสรุป HR ทั้งโรงเรียนจากข้อยกเว้นใน resolver เดิมของ staff list

แยกการเลือกคนเพื่อเพิ่มสมาชิกหน่วยงานไปใช้ staff lookup ที่มีข้อมูลขั้นต่ำและ authorization ของ workflow นั้น ทำให้ directory/aggregate ใช้ profile policy ตรงกันโดยไม่กระทบการเลือกสมาชิกที่ไม่จำเป็นต้องอ่าน profile รายละเอียด ทดสอบกรณีมีสิทธิ์อ่านตนเองร่วมกับสิทธิ์อื่นด้วย

รายการอ้างอิงอ่านได้เมื่อมีสิทธิ์อ่าน profile หรือมีสิทธิ์เพิ่ม/แก้ไขบุคลากร การเพิ่ม แก้ชื่อ และเปิด/ปิดรายการต้องมี `STAFF_UPDATE_ALL` ตามทะเบียนที่สร้างจาก contract หน้ารายการกลางเป็น child route ตามสิทธิ์นี้ ไม่เปิดเป็นเมนูอ่านสำหรับผู้ใช้ทั่วไป ไม่เพิ่ม permission code ใหม่โดยไม่จำเป็น

ใช้ route loader เป็นเจ้าของ primary reads และส่ง SvelteKit `fetch` ผ่าน API wrapper หน้า overview มีผลโหลดของ region เดียว เพราะตัวเลขและกราฟต้องใช้ scope/เวลา/ตัวกรองเดียวกัน พร้อม skeleton ก่อน paint, safe error, local retry, cancel/supersede และสถานะ refresh โดยคงข้อมูลที่ใช้งานได้ หน้ารายการกลางโหลดเฉพาะชนิดที่เปิดอยู่

ตัวเลือกของ filter/dialog และข้อมูลสำหรับ action โหลดเมื่อเปิดและผ่านสิทธิ์แล้ว ผู้มีสิทธิ์อ่านอย่างเดียวไม่ต้องโหลดข้อมูลของการจัดการรายการ เมื่อมี mutation ใช้ typed result ปรับส่วนที่เกี่ยวข้องหรือ invalidate dependency ที่ระบุ ไม่ใช้การ reload ทุกหน้าของระบบ

### DTO ของข้อมูลบุคลากร

แยก create staff info กับ update patch: ไม่ส่งช่อง = คงเดิม, ส่ง `null` = ล้างข้อมูล, ส่งค่า = เปลี่ยนค่า ใช้รูปแบบ nullable patch ที่มีตัวอย่างในโครงการ ไม่ใช้ `COALESCE` เพื่อกลืนคำสั่งล้างค่า ทั้ง request, database constraint และ generated schema ยืนยัน enum/FK ชุดเดียวกัน

response ส่ง ID และข้อมูล label ที่ join จากเจ้าของรายการกลางสำหรับการแสดงผล ไม่มี persisted สำเนาชื่อสาขาหรือสถาบันอีกชุด และไม่มี fallback กลับไปอ่านข้อความ legacy หลัง cutover ช่องใบอนุญาตและข้อมูลที่ไม่อยู่ในแบบฟอร์มต้องไม่ถูกล้างจากการแก้ข้อมูล HR

### ตำแหน่งโมดูล

ให้ `school-staff` เป็นเจ้าของ model, validation, reference service และ personnel aggregate service ส่วนแอปหลักเป็นเจ้าของ handler, router และ policy adapter ความสามารถทั้งหมดใช้บุคลากรและ tenant lifecycle เดิม จึงยังไม่แยก crate ใหม่ ไม่มี dependency ใหม่หรือหลักฐาน compile-scope ที่คุ้มกับการแยก ส่วน SQL/predicate ที่ directory และ aggregate ใช้ร่วมกันอยู่ใน module แคบของเจ้าของนี้ ไม่รวมงานวิชาการหรือ identity เข้ามา

## การย้ายข้อมูลเดิมและการเผยแพร่

ตรวจ migration timeline ก่อนเพิ่ม migration ถัดจาก `080` โดยไม่แก้ไฟล์ที่ใช้ไปแล้ว เพิ่ม schema, seed ตำแหน่ง, แปลงข้อมูลเดิม, reconcile และลบ owner ข้อความเดิมใน transaction เดียวภายใต้ maintenance ของ centralized tenant migration runner

วุฒิเดิม normalize เฉพาะชื่อและชื่อย่อที่ตรงกับ mapping ที่เขียนและทดสอบไว้ เช่น ปริญญาตรี/ป.ตรี → `bachelor` ค่าว่าง → `null` การมีข้อความไม่รู้จักหรือกำกวมต้องหยุด migration ก่อนเปลี่ยนข้อมูลและก่อนลบ column ไม่เปลี่ยนเป็น “อื่น ๆ” หรือเดาระดับให้อัตโนมัติ ใช้ข้อมูลจริงที่ตรวจอย่างปลอดภัยประกอบรายการ mapping ไม่อ้างว่าข้อมูล production ผ่านแล้วก่อนตรวจ

สาขาและสถาบันเดิมย้ายแต่ละชื่อที่มีความหมายไปเป็นรายการอ้างอิง เก็บความหมายของชื่อที่ไม่ว่าง และผูกแต่ละคนด้วย FK ตรวจจำนวนแถว staff info และความสัมพันธ์ก่อน/หลัง รวมทั้งจำนวนค่าที่ map ครบ ไม่ทิ้งค่าที่ใช้ไม่ได้ ถ้าพบค่าที่ normalize แล้วไม่สามารถเก็บได้ต้องหยุดและรายงาน finding ที่มีขอบเขต

ตำแหน่งและวิทยฐานะใหม่เริ่ม `null` สำหรับคนเดิม ผู้ดูแลเติมเมื่อทราบจริง ไม่ map จากบทบาทสิทธิ์หรือหน้าที่ในหน่วยงาน หลัง reconciliation ผ่านจึงเลิกใช้ persisted `major`/`university` text และให้ `education_level` รับเฉพาะรหัส canonical ไม่เหลือ dual read/write หรือสำเนา legacy ที่ไม่มีกำหนดจบ

ก่อนเผยแพร่ต้องมี read-only preflight ทุก tenant แสดงเพียงรหัส finding จำนวนรวม และผลผ่าน/ไม่ผ่าน ไม่ dump แถวบุคลากรหรือข้อมูลลับ หากมี unmapped degree ต้องให้ผู้มีสิทธิ์ตรวจและตกลง mapping/remediation ก่อน cutover ทดสอบ refusal นี้ทั้งที่ preflight และใน transaction ของ migration เพื่อป้องกันข้อมูลเปลี่ยนระหว่างตรวจและใช้งาน

ใช้ release แบบ `full` ประสาน migration/backend/contracts/frontend โดยเปิด maintenance จนทุก tenant อยู่ที่ version ล่าสุดและการตรวจผ่าน บันทึกขั้นตอนใน Operations ตามเจ้าของเดิม ฐานข้อมูลหลัง migration นี้ไม่รองรับ binary เก่าที่เขียนวุฒิเป็น free text หรืออ่าน major/university column เดิม หาก tenant ใดผ่าน migration แล้ว ห้ามย้อน deploy binary เก่า ให้คง maintenance และซ่อม forward ด้วย artifact ที่ตรวจแล้ว รักษา protected snapshot ตามขั้นตอนกู้คืนของโครงการและไม่แก้ SQLx history เพื่อให้ผ่าน

## เกณฑ์ยอมรับและการตรวจ

- Dashboard แสดงจำนวนจริงตาม scope มี unknown buckets และกราฟที่อ่านชื่อไทยได้ทั้ง desktop/mobile กรณีศูนย์ไม่มีกราฟหรือเปอร์เซ็นต์ผิดรูป
- กลุ่มสาระมาจากสังกัดเดิมเท่านั้น ทดสอบหลายสังกัด หลายหน่วยงานในกลุ่มเดียว สมาชิกที่ยังไม่เริ่ม/หมดอายุ และกลุ่มหรือหน่วยงานที่ปิดใช้งาน
- คลิกหมวดแล้วจำนวนรายชื่อเท่ากับกราฟภายใต้ scope/status เดียวกัน รวมหมวดที่ไม่มีข้อมูล กลับจากรายละเอียด/แก้ไขแล้วตัวกรองยังอยู่
- เพิ่ม แก้ไข ล้าง และแสดงข้อมูล HR ได้ เก็บค่าที่ไม่ได้ส่งไว้ ปฏิเสธ enum ผิด FK ต่างชนิดและการเลือก inactive ใหม่
- รายการกลางเพิ่ม/เปลี่ยนชื่อ/ปิดใช้งานได้ตามสิทธิ์ ชื่อซ้ำถูกปฏิเสธ คนเดิมยังอ่านค่า inactive ได้ read-only ไม่ร้องขอ action-only data
- database tests ใช้ fixture ที่ไม่มี PII จริง ยืนยัน mapping, ความสัมพันธ์/ข้อมูลเดิมครบ, safe retry, null/blank, unknown และ ambiguous, source drift, failure rollback และ refusal ของ cutover/cleanup โดยไม่ผ่าน reconciliation เพิ่ม guard กัน runtime legacy fallback กลับมา
- ทดสอบ authorization ทั้ง own/unit/tree/school และ denied รวม actor ที่มีสิทธิ์อื่นร่วมกับ own เพื่อป้องกันยอดหลุด scope ทดสอบ API mutation denial ไม่ตรวจเฉพาะการซ่อนปุ่ม
- ทำ backend focused tests ผ่าน rootless Podman runner, `cargo fmt --all -- --check`, `cargo test --test static_architecture`, `cargo check --workspace --all-targets` และ strict warning check ตามมาตรฐานโครงการ
- ทำ API generation/check/test, frontend lint/check/static/menu-sync/route-loading และ production-preview Playwright ที่ตรวจ dashboard/forms/catalog/drilldown/denied/mobile ใช้ credential จาก environment และปิด artifact ที่เก็บข้อมูลส่วนบุคคล
- เพิ่ม route-data inventory ของหน้าที่เพิ่ม ตรวจ diff และ tree ตาม `.rules` ก่อน integrate ไม่กล่าวอ้างว่าเร็วขึ้นโดยไม่มี timing/query plan รองรับ
- หลัง deploy ตรวจ migration/status ทุก tenant, readiness/smoke ตาม Operations, assets/routes และ acceptance แบบอ่านข้อมูลที่ได้รับอนุญาต ก่อนรายงานว่าเผยแพร่เสร็จ

## งานที่อยู่นอกขอบเขต

ไม่เพิ่มประวัติวุฒิหลายใบ ประวัติวิทยฐานะหรือจำนวนคนย้อนหลัง การประเมินสิทธิ์ขอวิทยฐานะ การคาดการณ์กำลังคน การ export รายงาน ระบบอนุมัติข้อมูล HR หรือการเปลี่ยน role/permission ของคนตามตำแหน่งงาน สิ่งเหล่านี้ไม่จำเป็นต่อการนับและจัดกลุ่มที่ผู้ใช้ขอ
