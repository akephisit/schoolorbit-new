# Inbox-first notifications

Approved architecture, 2026-10-26. `school-notifications` owns authoritative inbox acceptance and one-shot presentation. Producers own meaning, recipient snapshots, business identities, schedules and cancellation guards. Business mutations and all recipients' inbox rows commit together. Stable business keys replay the original IDs; changed source, recipient or content fails closed.

`NewNotification`, `NotificationSource` and `Presentation::{AlertOnce, InboxOnly}` form the typed producer API. Bulk `create_in_transaction` uses the caller's transaction; standalone `create` wraps it. Existing inbox wire fields and read state stay unchanged. Attendance, Workflow and Student Care preserve ledger IDs. Calendar reminders gain source identity and mark `sent_at` only with accepted inbox rows. Calendar mutation/request notifications join their owner transaction.

Presentation is a small durable record referencing the durable acceptance receipt. It expires after fifteen minutes by default, with the same fixed fifteen-minute browser cutoff; longer domain freshness requires future SSE expiry metadata. Workers validate source and inbox, then irreversibly consume pending work in PostgreSQL before SSE or Push. A process crash or uncertain transport/finish result never reopens consumed work. SSE and Push are independent. Each endpoint has a deadline; the batch has no deadline that can starve later devices. Tenant admission and database permits end before network I/O. Source deletion/cancellation and missing-inbox suppression remain fenced.

Authenticated device APIs are `GET /notifications/push/config`, `GET/POST /notifications/push/devices` and `DELETE /notifications/push/devices/{id}?version=uuid`. Registration takes `{installation_id,label,endpoint,p256dh,auth,key_id}`; `label` is one to eighty characters. Config returns `{available,public_key,key_id}`; devices return `{id,installation_id,label,version,binding_token,key_id,last_confirmed_at,expires_at}`. Bindings belong to the authenticated user and session, expire after ninety days and preserve version and binding token for an identical installation/endpoint/crypto/key/session refresh. Actual binding or key changes rotate both. Payloads contain generic lockscreen text, original validated app link (or `/`), expiry and exact device/version/binding identity for the service worker's local account fence. Revoked or expired sessions cannot receive Push. Device input validates known HTTPS providers, encoded crypto key lengths and bounded sizes. Global VAPID failures degrade Push only; only 404/410 retire the exact attempted device version. Endpoint/key/private-payload data never appears in logs. The arbitrary-recipient browser POST and old subscribe endpoint are removed.

Forward migration 139 locks notification owners under maintenance, audits historical payload/identity correspondence, preserves every existing inbox row and source ledger, and deterministically materializes only valid never-stored deferred rows (including prior claims that failed before storing) using original IDs. Previously stored or terminal work gets explicit legacy-skipped presentation, including absent terminal inboxes; it cannot emit a cutover toast. Migration 140 then reconciles the canonical projection and contracts dispatch rows into `notification_receipts`: exact IDs, source/idempotency, SHA256 SQL JSON-array payload identity, original creation/acceptance and legacy terminal timestamps, presentation policy and durable consumed/outcome evidence. Duplicate content and obsolete lease/retry scheduling fields are removed. `notification_presentations` retains only pending receipt references and expiry; consumption removes that transport detail atomically. No blanket deletion or inbox retention is introduced. Bounded cleanup removes terminal pending references immediately and stale devices after ninety days while preserving receipts and unread inbox.

Deploy matching backend, generated contracts and frontend together after quiescing old writers. Post-cutover recovery rolls forward; old dispatch binaries must not resume. Independent review and QA assess the complete candidate after writer freeze.
