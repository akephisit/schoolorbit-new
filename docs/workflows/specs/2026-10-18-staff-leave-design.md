# Staff leave and school exit

Approved scope: configurable staff leave and planned school exit, with separate menus and a shared staff-owned request lifecycle. School Staff owns request types, immutable effective policies, staff-category resolution, request revisions, reservation usage, audit and resource access. Workflow owns sequential process instances, assignment/My Work, durable notifications and reusable signature validation. Staff depends on Workflow; Workflow never imports Staff. This cohesive staff capability remains a module, avoiding a speculative crate split and its build overhead.

Types begin with sick leave, personal leave and school exit. They have no statutory quota defaults. An exit limit of 120 minutes is a school-editable local example, never a universal rule. Type code and kind are immutable. Archive prevents new requests; physical deletion is permitted only before any policy or request uses the type.

Policies are append-only profiles, each applying to explicit existing personnel categories. Each category resolves its most recent profile effective on the request start date; conflicting category/effective-date pairs are rejected. Updating one category does not remove other categories' profiles. A source reference and effective date are mandatory. Routing definitions are copied to an immutable workflow template owned by the policy version. Policies specify units, explicit calendar-day or school-configured working-day counting, annual year start month, optional per-request and annual limits, evidence and per-step signature settings. Working-day policies freeze ISO working weekdays and explicit excluded civil dates; generic calendar events are never assumed to be holidays. Advanced statutory entitlements remain explicitly unsupported.

The server derives usage: day means inclusive calendar dates or the policy-selected working dates; half_day means one morning or afternoon on one date (one half-day unit); minute means the difference between planned times on one date. The request carries full_day/morning/afternoon. Calendar periods never cross their policy quota year. Limits use policy units; an annual school-configured allowance is distinct from paid leave or legal entitlements. Submission serializes each staff/type/year ledger using a transaction lock and counts submitted reservations plus approved requests; draft, returned, rejected and cancelled requests consume no allowance. Cancellation pending retains its approved usage until cancellation approval.

The requester comes exclusively from the authenticated session. Personnel classification comes from Staff career history as of the request start date. Requesters create/edit drafts and returned requests, then submit. Submission pins the exact policy and content hash; reviewers may review, approve, reject or return. Owner and assigned access combine as a union, with explicit school scope covering all records. The requester cannot review their own request even with school permissions. Stale revisions fail; exact mutation retries reconcile to the same accepted outcome, while changed payloads with a reused key fail. Audit, revision, workflow and usage updates share one database transaction.

Approved cancellation is an audited second workflow purpose linked to the original request, retaining the original approval and content snapshot. Approval cancels and releases usage; rejection/return restores approved status. Draft/returned withdrawal is immediate; active withdrawal closes assignments through Workflow's public source-authorized provider. Repeated cancellation attempts have distinct immutable identities. There is no actual departure/return tracking or late alert.

The initial signature method is drawn signing with explicit owner consent, validated by Workflow and bound to exact request revision/content hash. No signature image is automatically reused. Evidence is private, owner-controlled, scanned/ready File Platform content; access is delegated to Staff request policy. Printable detail and CSV usage export obey the same scope as their JSON sources. Settings/routing directories require manage permission; personal options never disclose school directories.

API prefix `/api/staff-leave` uses typed envelopes and opt-in OpenAPI generation. Frontend consumes generated DTOs/permissions. Runtime endpoints are types, policies, personal options, administrative routing options, requests/detail/update/submit/actions/cancel and scoped usage. Thin Staff handlers use existing session/tenant extraction. Deployment is an additive migration and old binaries simply ignore new tables; no production operation is authorized by this artifact.
