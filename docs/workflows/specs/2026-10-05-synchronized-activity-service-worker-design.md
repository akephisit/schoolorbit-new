# Synchronized activity activation and worker recovery

Approved scope: adding an activity to an opening draft activates the offering immediately. Synchronized activities default to a central offering with target homerooms and a weekly target; reviewed groups remain optional at creation. Courses and independent activities retain group/teacher readiness requirements. Existing groups retain their teacher checks. Published opening graphs and timetables remain immutable; this change creates no production drafts or publications.

Delivery owns preparation metadata, draft creation and readiness. Timetable already schedules synchronized demands without groups and continues checking coverage, period counts and clashes. Keep these capabilities in their existing crates; no new crate, permission or migration is justified. Extend generated DTOs with preparation/catalog scheduling mode and central homeroom presentation states. Do not infer mode from activity names. Manual activity requests may explicitly request one group per target homeroom; creation and coverage share the offering transaction and retain the existing management scope. Central mode creates no groups.

Published-row activation selects a draft from the latest published source, reuses one eligible draft, asks among multiple, or opens the existing reason-only creation dialog. Historical views explain the latest-source behavior. Continue the pending catalog-ID intent only after navigation and authoritative draft loading. If already offered, navigate to its existing detail. Preserve pending intent on retry and clear it on cancellation/context change. Missing data produces an actionable error instead of a silent return. Consolidate the homeroom table into six correctly aligned columns.

The built worker is an ES module, while notification registration currently requests a classic worker. A shared registration owner starts from the root layout and serves push callers, using module type, the existing root scope, no script-cache updates, shared in-flight work, and a ten-second deadline. Disable Kit auto-registration. Remove fetch interception from the network-only worker; preserve push and click behavior. Update in place without unregistering subscriptions, clearing application data, or forcing page reloads. Failures do not block page mounting and are retryable.

Deploy matching backend/contracts/frontend through the coordinated release. No data cutover is needed. Verify fresh and previously controlled browser contexts on Chromium/WebKit, immutable published versions, and read-only SNWSB acceptance. The school currently has one published opening and one published timetable, with no drafts.
