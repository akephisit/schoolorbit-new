# Attendance and family experience

User-approved scope: the fourteen browser comments in this task. This design implements their requested behavior using the existing School owners.

- Settings use imported shadcn controls and 24-hour civil times. The processing calendar composes CalendarMonthGrid with authorized real calendar events; events inform decisions and never automatically alter counting. Reusable groups move to a focused dialog.
- Enrollment management exposes scoped identifiers and enrollment dates, never descriptors or photos. An independent loader read and a bounded searchable list support confirmed withdrawal; manual attendance remains available.
- Supervised scanning accepts stable matches across consecutive frames without requiring a turn in its fast mode. A selectable head-turn mode remains available. Recognition distance and ambiguity margins stay unchanged. One detector pass uses a frozen camera frame, bounds descriptor work to four faces, and crops evidence from that same frame. Captures are processed sequentially with existing immutable event IDs and replay recovery. Hidden tabs pause inference and cameras are disposed on exit.
- Student and parent summaries use real identity and academic context, working timetable/calendar/attendance destinations and the actual student code. Attendance belongs to each linked child. Shared personal timetable presentation hides irrelevant activity codes and class lists.
- A new forward migration repairs only the uncustomized academic_delivery label. Route metadata removes the generic parent attendance menu; backend linked-child authorization remains authoritative.

Owners: school-attendance owns metadata DTO/storage operations; root attendance adapter owns authorized academic scope; generated OpenAPI owns the API boundary. Existing frontend domain components and shared shadcn primitives own presentation. No new crate is justified: these are small capabilities within existing cohesive attendance owners, with no narrower independent dependency boundary. No biometric schema or recognition-model change is needed. The additive metadata endpoint and label migration preserve previous binary compatibility; normal coordinated release is sufficient.

Verification: disposable enrollment scope/removal and label-preservation cases; pure matching/tracking cases; synthetic browser settings, enrollment, multi-person scanning, child navigation and timetable cases; desktop/mobile in both themes; owned pipeline matrix, final rules/security review, Pipeline gate and deployed acceptance. Physical-camera distance/lighting and recognition accuracy require school-device acceptance and will not be inferred from synthetic tests.
