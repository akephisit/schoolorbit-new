# แบบระบบพฤติกรรมนักเรียนและการเชื่อมเช็กชื่อ

วันที่ 14 ตุลาคม 2026 — บันทึกแบบที่ผู้ใช้ตกลงในแชต แผนพัฒนาอยู่ใน [student-behavior](../plans/2026-10-14-student-behavior.md) ผู้ใช้อนุญาตให้เริ่มพัฒนาแล้ว และยืนยันว่าระบบยังไม่ถูกใช้งาน ไม่มีข้อมูลของบุคคลที่ต้องรองรับแบบเก่า

## ขอบเขต

ระบบพฤติกรรมนักเรียนแยกจากระบบเช็กชื่อ ใช้ตัวตนนักเรียนเดิมของ SchoolOrbit รองรับครูบันทึกพฤติกรรม การคิดคะแนนจากเช็กชื่อ ประวัติ รายงาน สิทธิ์ และการรีเซ็ตคะแนนพร้อมจัดการรายละเอียดเก่า ระบบติดตามช่วยเหลือยังอยู่นอกขอบเขต

## การบันทึกพฤติกรรม

- รายการแยกเป็นทำดีและทำผิด เลือกจากรายการที่กำหนดไว้ คะแนนในหน้าบันทึกอ่านอย่างเดียว Backend เป็นผู้ตัดสินคะแนนจากเกณฑ์ที่มีผล
- ข้อตกลงการทำงานเบื้องต้น: ครูแก้คะแนนต่อรายการไม่ได้ ผู้ดูแลปรับเกณฑ์สำหรับรายการใหม่ได้ เก็บเวอร์ชันและจำนวนที่ใช้จริง ไม่แก้ประวัติเดิมตามค่าใหม่
- วันและเวลาเริ่มต้นเป็นปัจจุบันตามเวลาโรงเรียน แก้เป็นวันเกิดเหตุได้ เก็บเวลาบันทึกจริงและผู้บันทึกจากระบบแยกต่างหาก มีรายละเอียดเพิ่มเติมแบบไม่บังคับ
- เลือกนักเรียนเป็นรายบุคคล ทั้งห้อง ทั้งระดับชั้น หรือผสมหลายห้องได้ เลือกทั้งหมดหมายถึงขอบเขตที่ระบุ ไม่ใช่เฉพาะหน้าที่มองเห็น
- รักษารายชื่อที่เลือกเมื่อค้นหา เปลี่ยนตัวกรอง หรือเปลี่ยนหน้า รวมคนซ้ำเป็นคนเดียว แสดงจำนวน รายชื่อ และผลต่อคนก่อนบันทึก
- บันทึกแบบกลุ่มเป็นหนึ่งชุดที่มีผลแยกรายคน ตรวจสิทธิ์และสมาชิกก่อนเขียน ไม่บันทึกบางส่วนโดยไม่แจ้ง ครูยกเลิกเฉพาะคนที่เลือกผิดได้

## เช็กชื่อ

มาโรงเรียน รายคาบ และรอบพิเศษใช้สถานะเดียวกันตามลำดับ: **มา / ขาด / สาย / หนีเรียน / ลาป่วย / ลากิจ / กิจกรรม / ยังไม่ได้เช็ค**

- หนีเรียนเป็นผลที่ครูเลือกเอง ไม่อนุมานจากการไม่พบผลเช็กชื่อ ใช้ได้ทั้งสามประเภทตามข้อกำหนดล่าสุด
- รายคาบและรอบพิเศษแสดงสถานะมาโรงเรียนในวันเดียวกันของนักเรียนแต่ละคนเป็นข้อมูลประกอบ ไม่คัดลอกเป็นผลของรอบที่กำลังเช็กโดยอัตโนมัติ
- ระหว่างวัน คนที่ไม่มีผลยังเป็นยังไม่ได้เช็ค หลัง 00:00 ของวันถัดไปในเขตเวลา Asia/Bangkok ปิดยอดวันก่อนหน้าและบันทึกขาดให้ผู้ที่ยังไม่มีผล เฉพาะวัน/รอบที่นับยอดและรายชื่อที่มีหน้าที่เข้าร่วม
- ไม่นับรอบยกเลิก คาบที่ไม่มีเรียน ผู้ที่ไม่อยู่ในรายชื่อของวันนั้น หรือรอบที่ไม่นับยอด ใช้รายชื่อและตารางเรียนตามวันเกิดเหตุ ไม่ใช้ห้องปัจจุบันแทนประวัติ
- Attendance เป็นเจ้าของผลขาดอัตโนมัติ เก็บที่มาและเวลาประมวลผลแยกจากวันเกิดเหตุ แล้วส่งการเปลี่ยนผลไปคิดคะแนน
- มีสถานะงานปิดยอดที่เก็บถาวร ทำซ้ำได้โดยไม่สร้างผลซ้ำ ประมวลผลวันที่ค้างหลัง restart ได้ ไม่ขึ้นกับการเปิดหน้าจอ และไม่เขียนผลเพียงเพราะผู้ใช้เปิดปฏิทิน
- เริ่มอัตโนมัติจากวันที่เปิดใช้ที่กำหนดไว้ ไม่เปลี่ยน unchecked ในอดีตทั้งหมดโดยปริยาย การคำนวณย้อนก่อนวันเปิดใช้ต้องมีขอบเขตและผลกระทบที่ตรวจสอบได้
- ปิดงวดคะแนนหลังปิดยอดเช็กชื่อวันสุดท้ายและส่งผลคะแนนครบ การแก้ผลที่ยังเปิดอยู่ใช้ revision/reason flow เดิม

## เกณฑ์คะแนนและการเชื่อม

- ทุกสถานะเลือกหนึ่งการกระทำ: ไม่คิดคะแนน เพิ่มความดี หรือหักคะแนน พร้อมจำนวน ตั้งการเชื่อมอัตโนมัติเริ่มต้นเป็นไม่คิดคะแนนจนโรงเรียนกำหนดเกณฑ์
- แยกเกณฑ์มาโรงเรียนและรายคาบ รอบพิเศษเลือกใช้ค่าเริ่มต้นรอบพิเศษหรือกำหนดเฉพาะรอบตอนสร้างได้ ไม่อ้างค่า mutable จนคะแนนเก่าเปลี่ยนเอง
- เกณฑ์มีวันเริ่มใช้ เวอร์ชัน และลำดับความเฉพาะเจาะจงที่ไม่กำกวม รองรับเกณฑ์กลาง/ระดับชั้น เพดานรายวัน และนโยบายคิดซ้ำระหว่างรอบ
- ข้อเสนอค่าเริ่มต้นการคิดซ้ำ: ขาดโรงเรียนทั้งวันไม่หักขาดรายคาบซ้ำ เปิดให้นับทั้งสองได้โดยตั้งชัดเจน รอบพิเศษตั้งว่าจะคิดเพิ่มหรือไม่
- คะแนนรายวันอิงผลมาโรงเรียนที่รวมเป็นผลเดียวต่อคน/วัน คะแนนรายคาบและรอบพิเศษอิงรอบ/คน ไม่คิดทุก arrival record เป็นคนละวัน
- ทุกช่องทางแก้เช็กชื่อ รวมถึง scan, correction, cancellation และ reset ต้องมีผลต่อคะแนนผ่านทางที่ทนต่อการส่งซ้ำและความขัดข้อง
- ผลคะแนนที่มาจาก Attendance แก้ต้นทางที่ Attendance ไม่ยกเลิกด้วยปุ่มยกเลิกพฤติกรรม

## คะแนนและรอบรีเซ็ต

เก็บจำนวนความดีและจำนวนคะแนนที่ถูกหักเป็นยอดแยก ค่าแสดงสุทธิ = ความดี − ถูกหัก ติดลบได้ ไม่ลบประวัติสองฝั่งเพราะแสดงสุทธิ

| ชุดคะแนน | ความหมาย |
| --- | --- |
| รอบปัจจุบัน | ยอดที่ใช้พิจารณาในรอบเปิดอยู่ |
| ประวัติแต่ละรอบ | ยอดที่ย้ายออกจากรอบปัจจุบันเมื่อปิดรอบ |
| สะสมทั้งหมด | ประวัติที่เก็บไว้ + ผลรอบปัจจุบัน โดยแต่ละผลมีเจ้าของเพียงชุดเดียว |

ตัวอย่างคะแนนหัก: ก่อนรีเซ็ต ปัจจุบัน 20/ประวัติ 0/สะสม 20; หลังรีเซ็ต 0/20/20; เมื่อถูกหักใหม่ 5 เป็น 5/20/25

- รอบคะแนนไม่จำเป็นต้องตรงภาคเรียน ตั้งรีเซ็ตเอง รายเดือน รายภาคเรียน หรือรายปีได้
- เลือกรีเซ็ตความดี คะแนนที่ถูกหัก หรือทั้งสองฝั่งได้ กรณีเริ่มรอบคนละเวลาแสดงขอบเขตของแต่ละฝั่ง สุทธิต้องเปรียบเทียบช่วงเดียวกัน
- ยอดประวัติเก็บแยกต่อคน/วัน/ฝั่ง/รอบ และที่มาเมื่อใช้กรองตามที่มา เพื่อรองรับการจัดการบางวันหลังลบรายละเอียดแล้ว ปีและภาคเรียนเป็นการรวมจากข้อมูลนี้ ไม่เป็นคะแนนอีกชุดที่ถูกบวกซ้ำ
- รอบที่ปิดเก็บแล้วอ่านอย่างเดียว การแก้เช็กชื่อเก่าหรือเพิ่มรายการย้อนหลังไม่ส่งคะแนนเข้ารอบใหม่และไม่แก้ยอดประวัติเงียบ ๆ การปรับประวัติใช้สิทธิ์ผู้ดูแลพร้อมเหตุผลและหลักฐานการปรับยอด

## การล้างข้อมูล

เลือกทั้งหมด ปี ภาคเรียน วัน หรือช่วงวัน เลือกฝั่งและที่มาได้ แสดงจำนวนคน รายการ คะแนน และผลต่อยอดทั้งสามชุดก่อนยืนยัน

| วิธี | รายละเอียด | ผลคะแนน |
| --- | --- | --- |
| ล้างรายละเอียด เก็บคะแนนไว้ | ลบจริง | เก็บผลย่อในชุดเดิม ปัจจุบันยังคงยอดเดิม |
| ย้ายคะแนนไปประวัติและล้างรายละเอียด | ลบจริง | ถอนจากปัจจุบันและเก็บในประวัติเพียงครั้งเดียว |
| ลบรายการและผลคะแนน | ลบจริง | ถอนผลจากชุดที่เลือก ไม่เก็บผลคะแนนนั้น |

รีเซ็ตทั้งรอบใช้วิธีย้ายคะแนนไปประวัติ ตรวจยอดก่อนลบแล้วเปิดรอบใหม่ที่ศูนย์ ลบรายละเอียดเหตุการณ์และข้อความที่ได้รับอนุญาตให้ล้าง ไม่คัดลอกข้อความเดิมไป audit หรือ JSON สำรองเพื่อซ่อนการเก็บรายละเอียด

เก็บเพียงข้อมูลสรุปที่จำเป็น บันทึกการล้าง และ metadata ป้องกัน source replay การล้างคะแนนไม่ลบ Attendance นักเรียนหรือเกณฑ์ คะแนนจากต้นทางในขอบเขตที่ล้าง/ปิดแล้วต้องไม่กลับมาเอง การล้างต้องประสานกับงานสร้างคะแนนเพื่อไม่ให้ข้อมูลกลับระหว่างลบ

หลังลบรายละเอียด ไม่สามารถยกเลิกเหตุการณ์รายรายการนั้นได้ การปรับยอดประวัติเป็นคำสั่งแยก การลบแถวช่วยลดข้อมูลรายละเอียดและเปิดพื้นที่ให้ฐานข้อมูลใช้ซ้ำ ไม่รับประกันว่าไฟล์ PostgreSQL จะหดทันที

## ประวัติ สิทธิ์ และตัวตน

- รายงานกรองนักเรียน ห้อง ระดับชั้น ช่วงวัน ฝั่ง ที่มา ผู้บันทึก และสถานะ รวมตัวกรองรายการที่ฉันบันทึก แสดงเหตุการณ์ ผู้บันทึก รายละเอียด จำนวนคะแนน และประวัติยกเลิกที่ยังไม่ถูกล้าง
- ครูยกเลิกรายการพฤติกรรมของตัวเองที่ยังมีรายละเอียดได้ พร้อมเหตุผล ผู้ดูแลยกเลิกของผู้อื่นได้ตามสิทธิ์ การยกเลิกซ้ำไม่คืนคะแนนซ้ำ
- แยกสิทธิ์อ่าน บันทึกตามขอบเขต ยกเลิกตนเอง ยกเลิกโรงเรียน ตั้งเกณฑ์ ปรับยอดประวัติ และล้าง/รีเซ็ต รองรับข้ามห้องเฉพาะเมื่อได้รับ scope ที่ครอบคลุม
- เชื่อมตัวตนนักเรียนด้วย UUID เดิมของ `users.id` และบริบทปี/ภาคเรียน รหัสนักเรียนสำหรับค้นหาและจับคู่ข้อมูลนำเข้า การเชื่อมระบบภายนอกใช้ mapping ไม่สมมติว่า UUID ตรงกัน

## ข้อมูลเดิมและการเปลี่ยนมาตรฐาน

แบบนี้เปลี่ยนข้อกำหนด unchecked เฉพาะหลังปิดยอด ปรับ [Attendance workflow semantics](../../../.rules) พร้อม runtime และ tests ในการพัฒนา โดยการเปิดหน้าจอยังคงไม่สร้างผลเช็กชื่อ

ใช้สถานะใหม่โดยตรง ไม่สร้าง generic-leave compatibility path หรือระบบจับคู่ข้อมูลเก่า ตามคำยืนยันว่าระบบยังไม่ถูกใช้ การเปลี่ยน schema ยังคงใช้ forward migrations และตรวจเงื่อนไขก่อนลบโครงสร้างเดิม หากพบข้อมูลที่ขัดกับคำยืนยันให้หยุดการลบแทนการเดาหรือทิ้งข้อมูล

การทำงานอิง [.rules](../../../.rules), [Testing](../../TESTING.md) และ [Operations](../../OPERATIONS.md) เอกสารนี้เป็น workflow input สำหรับงานเดียวและลบหลัง PR พัฒนาบันทึกผลที่เสร็จแล้วตามนโยบาย repository
