## Ownership and sequencing

Recipient-policy working agreement: resolve active students/recipients and guardian relationships once at business save/notification acceptance, then keep that recipient snapshot unchanged for delivery/retry. Generic direct send fetches the active recipient once in its own acceptance transaction and returns `RowNotFound` for missing/inactive accounts; lower-level enqueue trusts the producer-resolved snapshot. The worker retains source/job/module/cancellation identity and token guards, not activity/relationship rechecks. Physical account/job deletion still cancels, and migrated terminal/suppressed states remain closed. Retention and transient behavior remain unchanged.

Senior owns Git, migration numbering coordination, shared-checkout freezes, the one Cargo/build owner, integration and all production actions. Backend owns central provider/runtime/publisher, Attendance consumers and focused tests, root wiring/source-validity adapter and required existing dependency edges. Data owns new migrations119/120 and a dedicated root migration test target. A documentation writer owns `.rules` plus canonical Testing/Operations edits. Review is read-only; QA runs checks against frozen inputs and never repairs source. Assign explicit disjoint paths before each phase; no concurrent Cargo or broad formatter.

1. **Freeze and accept the architecture.** Senior and independent Review reconcile the design's provider signatures, typed source discriminator, thin ledger, lock order, fencing and strict migration-history boundary. Resolve implementation ambiguities in these artifacts before dependent writes. No additional user permission is needed for the already-authorized central ownership. Do not resume the obsolete queue checks/builds as acceptance of the replacement.

2. **Data: additive schema and atomic cutover fixtures.** Add119 for the empty central queue and indexes. Add120 to validate legacy identities/existing inbox consistency, copy every Attendance payload/state field, reconcile complete preservation, then drop only old queue payload/transport columns. Leave domain ledger identities and dedup intact. Add synthetic fixtures for pending, future leased, stored/unpublished, published/stored and published/null-stored suppression; preserve existing read inboxes and intentionally absent inboxes, and never reopen migrated terminal/suppressed jobs under the snapshot policy. Reject duplicate notification IDs, negative attempts, overlong inbox titles and recipient/payload collisions without normalization or replacement IDs. Prove these conflicts and forced reconciliation failures refuse contraction atomically; repair synthetic input and retry through the canonical migrator. Preserve both UUIDv7 queue identities and older notification UUID values. Migration119 is structurally additive only: exact timeline verification already prevents an118 binary from reacquiring after119. Never weaken schema verification or edit an applied migration.

3. **Backend: central provider and source-validity seam.** Implement typed enqueue, immediate store+enqueue, progress and cancellation operations. Define `DeliveryEligibilityPort` as a source/job-validity check, with stable-ID conflict rules and typed source decoding. Resolve recipient activity and guardian membership once in the producer save transaction; the central claim/materialization/ack path does not repeat them. Retain Attendance day guards1711 and first-wins ledger insertion; enqueue only newly inserted ledger rows, keeping ledger `created_at`. Return canonical identities in bulk and verify their agreement; do not confuse repeated arrival content with a stable-ID collision. Implement the Attendance provider and root composition without a central→Attendance dependency. Establish domain guard→queue→inbox order, sorted cancellation locks and token-fenced materialization/acknowledgement/suppression. A removed job or stale token must never create state or suppress a later claim. Never recreate a missing inbox whose job already has `stored_at`. Preserve source ownership filtering and same-transaction result save/queue rollback. Test provider behavior against the Data schema contract before changing runtime consumers.

4. **Backend: sole central dispatcher.** Move the bounded executor/unit test to the central owner and add directory/retry/wake orchestration:32 due rows, four unspawned items, five-second whole-item deadline,120-second fenced leases. Visit other tenants after each batch, defer failed admissions within a bounded deadline, retain no logical pool lease while idle and self-wake only for due work. Failed directory/schema admissions remain candidates for regular-tick retry, including startup before migrations finish; do not silently mark them empty or wait only for the300-second directory refresh. A restart or lost post-commit wake hint must discover persisted work. Add actual two-tenant backlog/failure tests and future-lease non-spin checks; do not add public test-only hooks or mirrored production algorithms.

5. **Backend: integrate consumers and remove obsolete paths.** Attendance result/digest transactions enqueue centrally and retain only its thin domain ledger. Remove its transport/claims/pending polling and move wake hints to the central owner after commit. Update reset to cancel owned central jobs before deleting inbox/source rows, and purge to use central progress while retaining stored/unpublished delivery. Wire one central worker at startup. Keep history's same-snapshot read-only helper. Convert `NotificationService::send` internally to immediate inbox+job transaction and central wake, retaining signature/returned ID and Calendar business post-commit behavior. The direct-send transaction performs one active recipient fetch and rejects missing/inactive accounts with `RowNotFound`; low-level enqueue trusts resolved recipients. No parallel module dispatcher, compatibility transport branch or detached per-message push task remains.

6. **Backend: transport outcomes and safe logs.** Preserve existing SSE/event payloads. Attempt sibling subscriptions, remove terminal invalid endpoints and propagate aggregate retryable failures so jobs are not falsely acknowledged. No subscriptions succeeds without VAPID. Replace raw endpoint/Debug-error logs with bounded safe codes/counts/UUIDs. Test subscription success, mixed terminal/retryable outcomes, configuration failure, whole-item timeout and stable-ID replay. Preserve the at-least-once limitation rather than claiming client receipt or ordering.
