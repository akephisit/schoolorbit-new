# Release cache and File/Workflow implementation plan

1. Pipeline: package the fixed release allowlist and emit a SHA/digest-bound identity from public preflight and deterministically reconstruct it privately. Implement strict host publication with existing Python 3; add rejection/replay fixtures before wiring transport, integrating installation into existing account-check or maintenance SSH.
2. Pipeline: replace four coordinated release SCP steps with one private-preflight upload after its interlock. Pin every coordinated release entrypoint to the immutable bundle. Separate executable/template reads from stable runtime journals/output; exercise legacy operation callers and existing gate fixtures.
3. Pipeline: extend Operations with a bounded exporter experiment phase, preserving current comparison/snapshot phases. Run fresh counterbalanced producer/consumer pairs using scratch registry state, frozen compiler cache and unchanged release flags. Include all variant-specific solve/export costs, digest imports, equivalence and failure cleanup evidence. Production selector changes require measured net gain and Senior agreement.
4. Backend: extract actual Workflow HTTP/PDF implementation into one owning crate; keep the core validation port and signing label, remove only demonstrated implementation edges, and update composition/API/architecture/test inventories. Preserve real renderer and database race fixtures.
5. Senior: pause writers for an early meaningful checkpoint, inspect/stage/commit and open the draft PR. Coordinate committed-source hosted exporter runs and serialized local Backend checks under disk/memory constraints; protected evidence and existing Docker containers are preserved.
6. Writers: fix owned failures and update canonical `.rules`, Operations and Testing with the final boundaries and executable recipes. Backend provides doc snippets to Pipeline, the single documentation writer.
7. Senior: freeze candidate, obtain independent complete-diff review and impact-based QA, repeat affected checks after repairs, record actual benchmark results and limits, and follow normal integration/deployment acceptance. Retire this plan/design after the PR records the outcome.

Selected Pipeline checks: focused bundle/public-private/workflow/maintenance/storage fixtures, exporter harness fixtures, `./scripts/pipeline verify --scope deployment`, documentation policy, scoped formatting, `git diff --check` and status. Docker runtime/OpenAPI and hosted benchmark evidence are separate from local fixture verification. Backend selects core/new-HTTP/consumer, persistence/race/PDF, architecture, normal/api-docs and offline API-equivalence checks; no concurrent Cargo or per-agent targets.
