# แผนพัฒนาเกณฑ์คำขอบุคลากร การเดินทางไปราชการ และการจัดสอนแทน

ขอบเขตตาม [แบบที่ผู้ใช้อนุมัติในแชตวันที่ 26 พฤศจิกายน 2569](../specs/2026-11-26-staff-travel-coverage-design.md) ใช้สาขาฟีเจอร์และ worktree ร่วมกันโดยแยกเจ้าของไฟล์ Senior จัดลำดับสัญญาและตัวสร้าง ตรวจการรวมงาน และส่งให้ Reviewer กับ QA ตรวจจาก candidate เดียวกัน

## ลำดับงาน

1. Backend Staff Leave เพิ่มแคตตาล็อกเกณฑ์แบบ typed ให้เรียกด้วยสิทธิ์จัดการเกณฑ์โรงเรียน เข้าถึงจาก Staff HTTP ผ่านเซสชันและ OpenAPI เดิม เกณฑ์กรอกเฉพาะข้อมูลอ้างอิงและค่าที่ระบุไว้ในแบบ ฝ่ายบุคคลบันทึกและเปิดใช้ผ่านการสร้างเวอร์ชันเกณฑ์เดิม
2. Backend Staff Leave เพิ่มประเภทเดินทางไปราชการ วัน เวลา จุดหมาย และผู้ร่วมเดินทางแบบหลายคนในสัญญาคำขอเดิม ตรวจประเภท ผู้ใช้ที่เกี่ยวข้อง และขอบเขตโรงเรียนก่อนยอมรับคำขอ ผูกการยืนยันของผู้ร่วมเดินทางกับคำขอที่ยื่นและผู้รับคำเชิญ ใช้รายการเดิมใน Workflow สำหรับการอนุมัติและยกเลิก เพิ่ม migration ตามลำดับโดยรักษาข้อมูลและหลักฐานเดิม
3. Backend เจ้าของตารางสอนตามวันที่จริงและ Staff Leave ขยายแผนให้ครอบคลุมคาบของผู้ยื่นและผู้ร่วมเดินทาง ใช้เจ้าของคาบในการคัดกรองครูสอนแทน การจอง และการสลับคืน ตรวจผลต่อการสอนรายวัน การเข้าเรียน และการปิดภาคเรียน
4. Frontend School ใช้ DTO ที่สร้างจากสัญญาเพื่อเพิ่มรายการเลือกเกณฑ์ในหน้าตั้งค่า เพิ่มชนิดคำขอทางราชการ และปรับแบบฟอร์มและรายละเอียดให้เลือกหลายคน แสดงการยืนยัน และจัดคาบตามเจ้าของคาบ ตรวจการทำงานตั้งแต่เริ่มร่างจนถึงส่งและตัดสินบนเดสก์ท็อปและมือถือ
5. Senior สร้างและตรวจสัญญา จากนั้น Reviewer และ QA ตรวจ candidate รวมตามเกณฑ์ด้านล่าง แก้ข้อบกพร่องกับเจ้าของไฟล์และทวนผลที่ได้รับผลกระทบ เก็บผลตรวจตาม workflow โครงการ

## ตรวจรับ

| ขอบเขต | สิ่งที่ต้องยืนยัน |
| --- | --- |
| เกณฑ์อ้างอิง | ผู้มีสิทธิ์เปิดและเลือกเกณฑ์ได้ ผู้ขอทั่วไปเข้าถึงไม่ได้ การเปิดหรือเลือกเกณฑ์ไม่มีผลต่อโรงเรียน ข้อมูลท้องถิ่นต้องตรวจและกรอกก่อนบันทึก เวอร์ชันเดิมยังเรียกได้ แหล่งอ้างอิงและคำแนะนำตรงกับกลุ่มบุคลากร |
| คำขอ | ลา ออกนอกสถานศึกษา และเดินทางไปราชการใช้ช่วงเวลาและหน่วยที่ถูกต้อง ปฏิเสธชนิด ช่วงเวลา จุดหมาย ผู้ร่วมเดินทาง หรือเวอร์ชันคำขอที่ไม่ผ่านเงื่อนไข |
| สิทธิ์และความเป็นส่วนตัว | การเข้าสู่ระบบ ขอบเขตโรงเรียน ขอบเขตคำขอ และ CSRF ใช้ Staff HTTP เดิม ผู้ร่วมเดินทางตอบแทนคนอื่นไม่ได้ สิทธิ์อ่านเอกสารประกอบคงขอบเขตที่กำหนด |
| การสอนแทน | คาบของแต่ละคนปรากฏหนึ่งครั้งตามเจ้าของและช่วงเวลาจริง ครูเดินทางที่ทับซ้อนเป็นครูทดแทนไม่ได้ การยืนยัน การสลับ การจองพร้อมกัน การส่งซ้ำ และการยกเลิกคงความถูกต้องของแผนและผลอ่านปลายทาง |
| ความคงอยู่ | migration บนฐานข้อมูลทดสอบรักษา ID เอกสาร เกณฑ์ นาที วัน ครึ่งวันในประวัติ เจ้าของคาบเดิม ลายเซ็น การยินยอม และข้อมูลอนุมัติ การลองซ้ำและธุรกรรมที่ล้มเหลวไม่มีข้อมูลค้าง |
| ประสบการณ์ใช้งาน | เลือกเกณฑ์แล้วตรวจและบันทึกเวอร์ชันได้ สร้างคำขอเดินทางที่มีผู้ร่วมหลายคน ผู้ร่วมเดินทางยืนยันจากมุมมองของตน จัดสอนแทนรายคน และรับข้อผิดพลาดพร้อมกลับมาทำต่อได้ |

ใช้ PostgreSQL แบบทิ้งได้ของตัวรันที่ระบุใน [คู่มือทดสอบ](../../TESTING.md) โดยใช้สภาพแวดล้อม Cargo ร่วมและให้ผู้รับผิดชอบการตรวจรันชุดต่อไปนี้จากรากโครงการ

```bash
./scripts/test_backend_school.sh --package school-staff-leave -- --test-threads=4
./scripts/test_backend_school.sh --integration staff_leave_coverage -- --test-threads=2
./scripts/test_backend_school.sh --integration staff_leave_lifecycle_obligations -- --test-threads=1
./scripts/test_backend_school.sh permission_coverage_staff_leave_coverage_uses_real_session_tenant_and_csrf_boundary -- --test-threads=1
git diff --check
git status --short
```

```bash
npm run generate:api-contracts
npm run check:api-contracts
npm run test:api-contracts
npm run check
npm run check:docs
E2E_BASE_URL=http://127.0.0.1:4173 npx playwright test tests/e2e/staff-leave.spec.ts tests/e2e/staff-leave-coverage.spec.ts --project=chromium --workers=1
```
