# Budget projects implementation plan

Implement the [already-approved design](../specs/2026-10-20-budget-projects-design.md) as one coherent feature under current [rules](../../../.rules). The Senior coordinates the shared feature branch, contracts, path assignments, Git, generators and one Rust build owner. Writers retain disjoint paths; final Reviewer and QA are independent. These stages describe remaining work, not completed checks.

1. **Establish boundaries — Senior and Backend.** Trace existing organization/staff, supply catalog, process, permission, file, work and notification providers and their actual consumers. Implement the cohesive `school-budget` owner with narrow ports/application adapters and validate crate-admission/compile-scope evidence. Agreed contracts use integer-satang strings, at-most-three-decimal quantities and exact half-up rounding once; allocation current budget (planned plus adjusted) is the spend ceiling without a separate baseline line cap. Preserve consumed line dimensions/history and freeze fiscal year/organization after the first accepted plan. Verify resource scopes and transition/revision/idempotency behavior against these decisions.
2. **Implement planning foundation — Backend writer.** Add owned schema, fiscal years/funds/expense categories, project/activity/line services, supply snapshots, explicit bulk defaults and bounded reads. Add draft/submit/review/return/approve and immutable accepted snapshots with amendments and audit. Preserve integer-satang string wire values. Register typed routes, OpenAPI and permission owners; Senior serializes contract generators. Test validation, arithmetic/rounding boundaries, references, tenant/resource denial, revisions, snapshot preservation and transaction rollback on disposable fixtures.
3. **Implement spending and adjustments — Backend writer, after foundation contracts.** Add activity-bound multi-line requests, approval reservations, partial/multiple payments with required voucher numbers and optional private evidence, closure release and add/reduce/transfer/loan/repay commands. Enforce fiscal-year/funding policy and idempotency under locked balance rechecks. Integrate process, private evidence, work and notification provider operations through their owning ports. Test concurrent approvals/payments/adjustments, replay/conflicting idempotency keys, stale edits, failed transactions, denied attachment access, outstanding loans and ledger reconciliation. Keep fixtures in the development-only owner.
4. **Build the workspace — Frontend writer, after agreed generated contracts.** Add dashboard, fiscal-year selection independent of academic context, project/detail/activity/line forms, requests/review, payments, adjustments, settings and reconciled reports/exports. Use generated DTOs and existing resource metadata and UI components. Keep four project form groups, name-only identity and explicit existing-line bulk changes. Handle regional loading/retry, empty and denied states, stale revisions and mutation feedback. Verify keyboard/pointer use and mobile/desktop in light/dark themes with synthetic APIs; viewing and scrolling must not write data.
5. **Reconcile and verify — owning writers, Senior coordinating.** Demonstrate the 9,928-baht mathematics example and funding/category pivot; verify dashboard, reports and exports agree with transactional balances. Run focused backend package/consumer and disposable-database tests selected after owner admission. If workspace composition changes, run `cargo check --workspace --all-targets` with the pinned toolchain and both applicable API-documentation modes. From `frontend-school`, run permission and API generation/check/tests for changed contracts, owning lint/type checks, focused helpers/components and affected Playwright workflows. Senior assigns shared generation/build slots. Run `git diff --check`, `git status --short` and `./scripts/pipeline verify --scope documentation`; select any additional matrix coverage from actual affected boundaries, without duplicating valid checks. Record exact commands, environment and tested tree; pending, failed and unavailable checks remain explicit.
6. **Freeze, review and repair — Senior, independent Reviewer and QA.** Pause every writer and source-mutating tool; freeze the full candidate. Reviewer inspects scope, provider ownership, permissions, private evidence, money/ledger invariants, migration preservation and test integrity. QA independently runs the selected behavior, concurrency, contract and browser checks. Senior sends findings to the responsible writer, freezes the repaired candidate and repeats affected review/checks until acceptance or a concrete reported blocker.
7. **Deliver — Senior.** Save meaningful checkpoints and open/update one draft PR early within authorized delivery scope. Before readiness/integration fetch latest main, confirm ancestry and apply the pause/save/merge/revalidation policy if it advanced. Keep incomplete work in draft. After accepted local evidence and independent review/QA, follow the existing latest-main Pipeline and merge gates through terminal status. Deploy migration 129/130 and matching backend/frontend/contracts under Maintenance Mode with all-tenant migration, readiness and deployed acceptance. Validate immutable attempt mapping and known adjustment revision preservation; strict compiled history blocks pre-129 binaries after 129 regardless of additivity, and recovery rolls forward without editing checksums. Use canonical Budget sections in `docs/TESTING.md` and `docs/OPERATIONS.md` for commands/setup/recovery. Record actual results in the PR; retain temporary artifacts until the PR records the completed outcome and the Senior assigns their removal.
